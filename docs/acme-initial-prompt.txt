HIGH-LEVEL ARCHITECTURE
Use this architecture:

1) Frontend – Next.js App
- **Next.js 14+ with App Router**.
- **Tailwind CSS** for styling, configured to produce the premium UI described above.
- Chat widget:
  - Floating button + slide‑up panel as described.
  - Message list with user/bot bubbles, timestamps, auto‑scroll, typing indicator, loading states.
  - Mobile and desktop responsive, consistent look and spacing.
- Admin panel:
  - Protected route (simple auth).
  - Pages:
    - Documents: upload (drag‑and‑drop), list (name, type, status, last updated).
    - Analytics: total conversations, top questions, basic charts.
    - Settings: model name, temperature, top‑k retrieval, etc.

2) Backend – API + RAG
Prefer **Python FastAPI** (or Node.js/Express if you must), but keep code clean and modular.

RAG pipeline:
- Ingest documents from a local folder (simulate help center + internal docs with markdown/txt/HTML).
- Use **LangChain** (or similar) to:
  - Load and normalize docs.
  - Chunk with a sensible strategy (overlap, max tokens).
  - Compute embeddings with **OpenAI embeddings**.
  - Store vectors in a vector DB (Chroma is fine locally).
- Retrieval:
  - Given a query, retrieve top‑k chunks.
  - Construct a prompt that:
    - Includes retrieved context.
    - Enforces: *answer ONLY from context; if not present, say you’re not sure and escalate*.
- Chat API:
  - `POST /api/chat`: `{ sessionId, message }` → `{ answer, sources, metadata }`.
  - Maintain simple per‑session history in a relational DB (Postgres/SQLite is fine).
- Health endpoint:
  - `GET /api/health` returns basic status.

3) Data & Storage
- **Vector DB**: Chroma (local) with clear abstraction so it can be swapped to Pinecone later.
- **Relational DB**: SQLite or Postgres for:
  - Conversation logs.
  - Document metadata.
- Provide a seed script that:
  - Loads a small set of example docs (e.g. markdown files under `data/docs/`).
  - Builds the index.
